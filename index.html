// SMART ROUTING ARCHITECTURE

Project Kash uses dynamic request routing in Next.js to minimize API round-trips and optimize throughput when interacting with serverless backends:

01
Client Request Interception: Edge routes validate incoming payload schemas before passing data downstream.
02
Intelligent API Caching: Frequently accessed financial categories are cached with staggered revalidation triggers.
03
Batch Sync Queue: Multi-entry financial allocations are batched into single HTTP payloads to prevent hitting Google API rate limits.

// SERVER-SIDE OVERDRAFT PROTECTION

In Zero-Based Budgeting, every dollar must equal zero ($Income - $Allocations = 0). Kash enforces this with strict server-side transaction assertions:

async function validateTransaction(payload) {
  const currentBalance = await fetchLiveLedgerBalance();
  if (payload.amount > currentBalance.unallocated) {
    throw new Error("OVERDRAFT_PREVENTED: Zero-based budget allocation exceeded");
  }
  return await commitToGoogleSheetsServiceAccount(payload);
}

This mechanism prevents client-side tampering by guaranteeing that balance updates are verified server-side before persisting to the Google Sheets backend.
